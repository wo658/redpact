# 결과와 스크린샷

Redpact에 실행을 요청한 프로젝트와 워크트리를 선택하세요. 결과를 해석하기 전에 실행 식별자와 기록 시각을 확인하세요. 현재 파일은 실행 후 바뀔 수 있습니다. 저장된 결과는 해당 실행에서 받아들인 입력을 설명합니다.

아직 증거가 없다면 [첫 실행](first-run.md)을 따라 하세요. 실행 경로는 [테스트 작성과 실행](tests.md)을 참고하세요.

## 알맞은 화면 찾기

| 화면 | 확인할 내용 |
|---|---|
| 프로젝트 **Tests** | 기본 체크아웃의 현재 Unit·Integration 파일과 실행 결과 |
| 워크트리 **Unit Test** | 조건에 맞는 변경 소스와 명령 결과 |
| 워크트리 Integration 검토 | 제출한 케이스, 기록된 소스, 실행 증거 |
| 워크트리 **Playwright** | 선택한 Desktop·Mobile 크기의 PNG checkpoint가 기록된 capture 목적 파일 |
| 프로젝트 **Tests → Playwright → Screenshots** | 프로젝트 타깃과 기록된 워크트리 타깃의 현재 이름별 캡처 |
| 프로젝트 **Tests → Playwright → Tests** | 아직 실행하지 않은 소스를 포함한 유지되는 기능 파일 |
| 프로젝트 **Tests → Playwright → Runs** | 워크트리와 두 범위를 아우르는 보존된 실행 |
| 워크트리 **Log** | 복사 가능한 진단 자료를 포함한 Unit·Integration·Playwright 요약 |

페이지를 열거나 소스를 선택하는 작업은 읽기 전용입니다. 명시적인 실행 작업으로 테스트가 시작됩니다. Tests에 파일이 표시된다고 통과했다는 뜻은 아닙니다.

워크트리 **Playwright**는 선택한 Desktop·Mobile 크기에 대응하는 최신 실행에 PNG가 있는 capture 목적 파일을 나열합니다. 워크트리 초안과 변경된 프로젝트 캡처 소스를 따르며 변경 없는 유지 소스는 프로젝트 Tests에서 봅니다. 기능 결과는 Tests와 Log에 있습니다. 최신 실행에 이미지가 없으면 과거 이미지로 대체하지 않습니다. 기록된 캡처 viewport 너비로 크기를 필터링하며 정보가 없으면 두 모드에서 표시하고 표기합니다. 비어 있음이 확인된 검토 탭은 숨기되 오류·활성 실행·정리는 접근 가능하게 유지합니다.

## 변경된 테스트 코드 검토하기

워크트리 Unit 및 Integration의 **Code** 패널은 **Diff**와 같은 Git 비교를 사용하여 추가·삭제된 줄, 주변 문맥과 줄 번호를 표시합니다. Changes/Full code 전환은 제공하지 않습니다. 패치를 사용할 수 없거나, 패치가 생략되었거나, 해당 파일이 없거나, 파일 목록과 비교 기준이 다르면 전체 소스로 대체하지 않고 **Changes unavailable.** 안내를 표시합니다.

프로젝트 전체 테스트 목록은 전체 소스 보기를 유지합니다. 기록된 Integration 실행 소스는 변경되지 않으며 현재 워크트리 변경과 구분됩니다.

## 테스트 결과 읽기

**Unit**에서는 명령, 종료 코드, stdout/stderr, 정리 상태를 확인하세요. 결과는 개별 케이스가 아닌 명령 전체를 설명합니다. 소스를 선택했다고 해당 파일만 실행된 것은 아닙니다. 소스 뷰어는 보관된 단위 테스트 소스 스냅샷이 아닌 현재 파일을 읽습니다.

**Integration**에서는 수집된 소스, 케이스 판정, 관찰된 단계를 확인하세요. 의미 있는 어설션에 도달했는지 확인하세요. 건너뛴 케이스나 테스트 본문 이전의 실패에는 관찰된 단계가 없을 수 있습니다. 완료되지 않은 단계는 통과가 아닙니다. 에이전트는 `get_run`으로 통합 테스트 증거를 가져옵니다.

**Playwright**에서는 타깃, 범위, 목적, 시나리오와 단계 결과, 첨부 파일을 확인하세요. 기능 테스트 성공은 실행된 어설션이 통과했다는 뜻입니다. 캡처 성공은 시나리오가 완료되었다는 뜻이며, 시각적 판단은 여전히 사람이 이미지를 확인해야 합니다.

다음 결과를 구분하세요.

- **어설션 실패:** 확인 단계에 도달했지만 실제 동작이 기대와 일치하지 않았습니다.
- **준비 또는 실행 오류:** 수집, 설정, 환경 준비, 실행기에서 실패했습니다. 제품 어설션의 실패를 입증하지 않습니다.
- **취소 또는 중단:** 실행이 정상적으로 끝나지 않았습니다. 어떤 케이스가 완료되었는지 확인하세요.
- **리소스 제한:** 기록된 메모리 또는 시간 제한을 초과했습니다. 원인과 적용된 제한을 확인하세요.
- **정리 오류:** 리소스 제거가 실패했습니다. 테스트 판정과 함께 읽으세요.

다음 조치는 [문제 해결](troubleshooting.md)을 참고하세요.

## 현재 스크린샷 둘러보기

**Tests → Playwright → Screenshots**에서 이미지를 선택하세요. `Settings / Appearance / Dark theme` 같은 이름은 페이지와 기능별 그룹으로 표시되며 마지막 부분이 이미지 이름이 됩니다.

갤러리는 **캡처 타깃별로** 가장 최근에 성공적으로 완료된 실행을 사용합니다. 해당 타깃이 성공한 적이 없다면 가장 최근 완료된 실행을 사용합니다. 더 새로운 성공 실행은 전체 이름 집합을 교체하므로 사라진 시나리오와 이름이 바뀐 그룹은 현재 목록에서 제거됩니다. 실패한 재시도는 성공한 집합을 대체하지 않습니다.

따라서 “현재”는 표시 정책을 뜻하며 모든 이미지가 최신 파일을 반영한다는 보장은 아닙니다. 시각과 소스를 확인하세요. 서로 다른 타깃의 이미지가 서로 다른 실행에서 왔을 수 있습니다. 소스 변경 표시가 있다면 현재 코드의 증거로 사용하기 전에 다시 실행해야 합니다.

워크트리 범위의 캡처는 초안을 정리한 뒤에도 기록된 시나리오 원본과 함께 이 갤러리에 표시됩니다. 내장 진단 스크린샷은 갤러리에 포함되지 않습니다. 이전 또는 실패한 작업 캡처는 Runs에서 찾으세요.

## 과거 캡처 열기

**Tests → Playwright → Runs**에서 실행을 선택하고 스크린샷이나 진단 첨부 파일을 여세요. Runs는 원래 이름, 수집된 시나리오 소스, 단계, 결과를 보존합니다. 두 범위와 제거된 체크아웃의 증거도 포함합니다.

갤러리에서 이름이 바뀌거나 제거되거나 교체된 이미지는 Runs에서 찾으세요. 현재 파일이 이미지를 만들었다고 가정하지 말고 소스 링크에서 수집된 시나리오를 읽으세요. 워크트리 초안 코드를 제거해도 기록된 소스와 이미지는 보존됩니다.

스크린샷은 실시간 프리뷰가 아닌 정적인 증거입니다. 맞춤 표시와 원본 크기 컨트롤은 표시 배율을 바꾸며 캡처된 뷰포트를 바꾸지 않습니다. 새 타깃은 선택한 워크트리를 한 번 실행합니다. 뷰어는 자동 전후 비교 실행이나 시각적 승인을 제공하지 않습니다.

## 로그 확인과 진단 자료 공유

워크트리 **Log**를 여세요. 각 행에 테스트 종류, 의도, 상태, 생성 시각이 표시됩니다. **Older executions**로 이전 이력을 보고 **Newest executions**로 돌아오세요. 복사 작업은 해당 실행에 기록된 진단 텍스트를 가져옵니다.

Unit 로그에는 크기가 제한된 명령 출력이 포함됩니다. Integration 로그에는 보존된 실행 진단이 포함됩니다. Playwright 로그에는 기록된 케이스, 단계, 오류가 포함되며 브라우저 콘솔 원문 전체를 제공하지는 않습니다.

에이전트에게 조사를 요청할 때 실행 ID, 선택한 워크트리, 결과, 관련 오류를 포함하세요. 이후의 통과 결과가 의도한 수정과 연결되도록 재시도 사이에도 원래 실패를 보존하세요. 표시된 상태를 신뢰하기 전에 로딩 오류나 오래된 증거 안내를 해결하세요.

## 변경 하나를 소스부터 결과까지 검토하기

“계정 설정 저장” 변경이라면 먼저 의도한 동작을 정리하세요. 유효한 값을 저장하면 값이 유지되고 완료 안내가 보여야 한다고 가정해 보겠습니다. 다음 순서로 근거를 확인할 수 있습니다.

1. 해당 실행을 열고 체크아웃과 시각을 확인합니다.
2. 기록된 Integration 또는 Playwright 시나리오를 읽습니다. 저장 동작을 수행하고 예상 결과를 검사하는지 확인합니다.
3. 관찰된 단계를 살펴봅니다. 저장, 다시 읽기, 단언이 실제로 완료됐는지 확인합니다.
4. 이름이 붙은 캡처를 열어 화면 상태를 판단합니다. 성공 메시지만으로 데이터 유지까지 확인되지는 않을 수 있습니다.
5. 현재 소스와 실행 당시 소스를 비교합니다. 이후 관련 코드가 바뀌었다면 다시 실행하도록 요청합니다.

결론은 구체적으로 작성하세요. “기록된 브라우저 테스트가 폼을 제출하고 새로고침 후 저장값을 확인했으며, 첨부 캡처는 완료 안내 상태를 보여준다”처럼 설명할 수 있습니다. 근거가 없다면 모든 설정, 화면 크기, 오류 경로가 검증됐다는 주장으로 넓히지 마세요.

## 이전 이미지가 계속 보이는 이유

유지되는 캡처 타깃이 월요일에 성공하고 화요일 재시도 중 실패했다고 가정해 보겠습니다. 현재 Screenshots 갤러리는 월요일의 성공한 이미지 집합을 유지합니다. 화요일의 실패한 시도는 Runs에서 볼 수 있습니다. 갤러리는 완성된 장면을 둘러보는 데 유용하고, Runs는 특정 시도에서 무슨 일이 있었는지 알려줍니다.

수요일의 성공 실행에서 장면 이름이 바뀌면 현재 갤러리는 그 타깃에 대해 수요일의 전체 집합을 사용합니다. 월요일의 이전 이름은 월요일 기록에 남습니다. 특히 시나리오 이름을 바꾸거나 제거한 뒤에는 실행 식별자와 기록 시각을 함께 확인하세요.

## 에이전트에게 후속 작업 요청하기

관찰된 불일치와 이를 보여주는 기록을 포함하세요. 예를 들어 다음과 같이 요청할 수 있습니다.

> 이 체크아웃의 기록된 Playwright 실행에서 저장 단계는 완료됐지만 새로고침 후 값이 되돌아갔어. 해당 실행의 소스와 실패한 단언을 확인하고, 저장 동작을 고친 뒤 같은 검증 의도로 다시 실행해줘. 두 실행 ID와 새 실행의 정리 상태를 알려줘.

화면 문제라면 캡처 이름과 눈에 보이는 문제를 설명하세요. 설정 문제라면 환경 준비 오류를 포함하세요. 이렇게 하면 다음 조사에 명확한 출발점을 제공하고 원래 실패와 수정의 연결을 유지할 수 있습니다.

## 리소스와 소스 보존 이해하기

모든 실행은 자체 임시 리소스를 사용하고 완료·실패·취소 후 정리합니다. 독립적인 테스트 환경 준비와 재사용은 지원하지 않습니다. 수동 점검에는 별도 Project Container를 사용합니다. 정리에 실패하면 리소스가 남을 수 있습니다. Unit 컨테이너 정리는 해당 실행 상세에서 재시도하고, 관리되는 애플리케이션 리소스는 환경 컨트롤을 사용하세요. 필요하면 뷰어의 취소와 환경 컨트롤을 사용하세요. 모델용 MCP 도구는 취소나 환경 중지 작업을 제공하지 않습니다.

**Clean up worktree code**는 검사를 통과한 뒤에만 기록된 Playwright 작업 초안을 제거합니다. 과거 증거는 남습니다. Unit 런타임 입력 사본은 정리 중 제거되지만 명령 증거는 남습니다. Integration 제출은 수집된 테스트 번들을 보존합니다.

[설정](configuration.md)이나 실행 선택을 바꾸면 이후 요청에 적용됩니다. 이전 결과를 다시 쓰거나 기존 환경을 재설정하지는 않습니다. [문서 개요](index.md)로 돌아가세요.
