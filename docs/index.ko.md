# 채팅으로 개발하고 Redpact로 검토하기

코딩 에이전트에게 격리된 워크트리에서 TDD로 변경을 구현하도록 요청하세요.
Redpact는 실행 입력을 캡처하고 Unit·Integration·Playwright 검증을 실행하며,
사람의 판단이 필요한 때 정확한 요청이나 결과 기록을 엽니다.

| 담당 | 책임 |
| --- | --- |
| 호스트 대화와 에이전트 | 워크트리, 하위 에이전트, 파일, 설정, 로컬 TDD, Git과 게시 |
| Redpact MCP | 설정 진단, 관리형 실행, 상태, 취소와 근거 조회 |
| Redpact 뷰어와 Apps | 사람의 실행 승인, 기록된 소스·결과·화면과 워크트리별 이력 |

뷰어는 채팅에서 받은 실행 링크를 엽니다. 이력은 그 기록의 워크트리에 묶입니다.
실행 맥락이 없으면 대화에서 기록을 열도록 안내합니다. 프로젝트 관리, 설정 편집기,
테스트 실행 카탈로그, 수동 컨테이너와 Git 작업은 뷰어의 역할이 아닙니다.

> 워크트리에서 TDD로 수량 편집을 구현해줘. 의도한 단언 실패를 먼저 확인하고
> 구현해. 독립 작업은 하위 에이전트에게 나눠 맡겨. 이 체크아웃에서 관리형 API와
> 브라우저 검증을 요청하고 실제 실행 링크, 데스크톱·모바일 캡처와 남은 검토 결정을 알려줘.

Ask에서는 사람이 MCP App이나 연결된 검토 화면에서 캡처된 요청을 승인합니다.
실행 승인은 코드 변경의 수락이 아닙니다. 통과 결과, 현재 소스의 최신성, 사람의
수락은 별개입니다. 수집 오류나 환경 실패는 TDD 단언 실패를 증명하지 않습니다.

[설치](installation.md), [설정](configuration.md), [검토 절차](review-workflow.md)부터
시작하세요. [결과](results.md)는 근거를, [테스트 작성](tests.md)은 지원 런타임을
설명합니다. 모든 워크트리는 하나의 고정 설정을 공유하지만 각 실행의 임시 자원은
독립적입니다. [의존성](dependencies.md)을 참고하세요.

Redpact는 정식 출시 전입니다. 이 문서는 구현을 설명하며 로컬 프로젝트에 직접 연결하지 않습니다.
