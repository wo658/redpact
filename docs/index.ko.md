# 채팅으로 개발하고 Redpact로 검토하기

Redpact는 코딩 대화와 관리형 검증, 사람의 검토를 연결합니다.
에이전트에게 격리된 워크트리에서 변경을 구현하고, 실패하는 테스트를 먼저 확인한 뒤,
실제 애플리케이션에 대한 검증을 기록하도록 요청하세요. 실행 승인, 실패 조사,
기록된 화면과 소스에 대한 판단이 필요할 때 Redpact를 엽니다.

## 하나의 대화, 함께 보는 근거

```mermaid
flowchart LR
    A["변경 요청"] --> W["에이전트: 워크트리와 실패 테스트"]
    W --> I["에이전트: 구현 후 검증 요청"]
    I --> X["Redpact: 승인, 실행, 근거 기록"]
    X --> R["사람: 근거 검토"]
    R --> A
```

호스트 에이전트는 코드와 설정을 편집하고 Git 작업을 수행합니다. Redpact는 Unit,
Integration, Playwright 검증을 실행하고 실제 결과를 기록하여 대화와 뷰어에서 같은
근거를 확인하게 합니다. 하위 에이전트가 일을 나누더라도 총괄 에이전트는 의도한
체크아웃에서 통합된 결과를 검증해야 합니다.

로컬에서 관찰한 assertion 실패는 TDD 과정의 근거입니다. 등록된 요청, 정적으로 읽은
테스트, 환경 준비 실패만으로 assertion이 실행됐다고 할 수 없습니다. 관찰한 red·green
근거와 사용자의 변경 수락을 구분합니다.

## 각 화면과 도구의 역할

| 영역 | 책임 |
| --- | --- |
| 채팅과 MCP | 체크아웃 상태 조회, 설정 진단, 실행·취소 요청, 근거 조회와 남은 작업 설명 |
| Redpact 뷰어 | 현재 작업, 실행 이력, 특정 실행 근거와 리소스 문제 |
| 승인 카드 | 캡처된 실행 요청에 대한 사람의 결정 |
| 호스트 에이전트와 편집기 | 워크트리, 파일 편집, diff, 커밋, PR과 머지 |

기본 뷰어는 검토 작업 공간입니다. 일반 파일 탐색, Git Graph, 독립적인 작업 공간 탭은
이 인터페이스에 포함하지 않습니다. 필요할 때 고급 테스트 목록, 수동 Container,
설정에 접근할 수 있습니다. 정확한 경로는 [뷰어 탐색](ux-navigation.md)을 참고하세요.

## 검증할 수 있는 변경 요청하기

> 격리된 워크트리에서 주문 수량 편집을 구현해줘. 먼저 요청한 동작에 대한 테스트가
> 실패하는 걸 확인하고 구현해. Redpact로 이 체크아웃의 관련 검증을 실행하고,
> 데스크톱과 모바일 사용자 상태를 캡처해. 기록된 근거와 내가 결정할 사항을 알려줘.

에이전트는 체크아웃 상태와 공유 설정부터 확인합니다. 테스트 종류에 맞는 MCP로
실행하며, 승인이 필요하면 사람이 지원되는 App 컨트롤이나 연결된 실행 검토 화면에서
승인할 때까지 대기합니다.
검토 링크는 같은 로컬 인스턴스와 실행을 가리킵니다.
[첫 변경 검토](review-workflow.md)에서 전체 흐름을 확인하세요.

## 서로 독립적인 세 가지 사실

통과 결과는 실행된 assertion이나 명령의 결과입니다. 현재 파일이 당시 입력과 같은지,
사람이 변경을 수락했는지까지 증명하지 않습니다. Redpact는 실행 결과, 소스 최신성,
사람의 수락을 구분합니다. 최신성이 불명확하면 그대로 표시하며, 에이전트나 상태
배지가 승인을 만들어내지 않습니다.

모든 워크트리는 하나의 고정 설정을 공유하지만 각 실행은 새 임시 리소스를 소유합니다.
어떤 서비스가 격리되고 어떤 외부 데이터가 공유되는지는
[의존성과 워크트리](dependencies.md)를 읽어보세요.

[설치](installation.md), [프로젝트 설정](first-project.md),
[첫 실행](first-run.md)으로 시작하세요. 근거 해석은 [결과](results.md),
검증 확장은 [테스트 작성](tests.md)을 참고하세요. Redpact는 정식 출시 전이며,
이 사이트는 구현을 설명할 뿐 로컬 프로젝트에 직접 연결하지 않습니다.
