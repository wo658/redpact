# 체크아웃 식별과 Git

호스트 에이전트가 워크트리 생성, 브랜치, 스테이징, 커밋, 병합과 풀 리퀘스트를
담당합니다. Redpact는 Git 관리 화면이나 변경 API를 제공하지 않습니다.
사용자가 허용한 범위에서 호스트의 네이티브 Git 도구를 사용하세요.

## 기존 체크아웃 연결

Redpact는 설정된 루트와 네이티브 Git 워크트리 등록을 관찰합니다. 저장소 하위
디렉터리는 연결된 워크트리를 찾을 때 애플리케이션의 상대 루트를 유지합니다.
디렉터리 프로젝트는 설정된 디렉터리에 묶입니다. 읽기 전용 탐색은 체크아웃 생성,
프로젝트 설정 변경이나 애플리케이션 코드 실행을 하지 않습니다.

실행은 명시한 기존 체크아웃을 사용합니다. 공유 기본 체크아웃이
`.redpact/settings.json`을 소유하고 Compose, Dockerfile, 애플리케이션 소스와
테스트는 실행 체크아웃에서 해석합니다. [설정](configuration.md)을 참고하세요.

네이티브 Git 조회는 실행에 필요한 소스 식별과 비교를 제공합니다. 실행에 캡처된
Git 식별은 과거 근거이며 저장소 변경 권한이 아닙니다. 체크아웃이 사라지거나
이동해도 이력은 남을 수 있지만 새 실행은 불가능할 수 있습니다. 다른 체크아웃으로
조용히 대체하면 안 됩니다.

## 검토와 정리

반환된 실행 식별과 검토 링크를 사용하세요. 워크트리별 이력은 기록된 체크아웃의
시도를 보여주며 체크아웃 삭제 후에도 근거를 보존합니다. 관련 현재 입력을 실제로
비교하지 않았다면 소스 최신성은 알 수 없는 상태입니다.

커밋·PR·병합 결정은 호스트 대화에서 합니다. 실행 승인과 테스트 통과는 그 권한을
부여하지 않습니다. 워크트리를 삭제할 때 필요한 파일과 과거 근거를 보존하고 저장소의
워크트리 정책을 따르세요. 런타임 자원 정리는 Git 정리와 별개입니다.
소유권과 복구는 [실행](execution.md), [저장소](storage.md)에 설명합니다.
