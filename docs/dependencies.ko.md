# 의존성과 워크트리

앱은 격리된 PostgreSQL, 관리형 결제 mock, 공유 로컬 검색과 원격 API를 함께 사용할 수
있습니다. 기본 체크아웃의 `.redpact/settings.json`에 이 고정 구성을 한 번 정의하고
연결된 모든 워크트리가 공유합니다. 의존성은 연동 서비스이며 Docker 빌드에서 설치하는
npm 패키지 목록이 아닙니다.

| 종류 | 준비와 정리 |
| --- | --- |
| `isolated` | 실행마다 Compose가 선언된 의존성 서비스를 시작합니다 |
| `mock` | Compose가 구현된 대체 서비스를 시작하거나 바인딩이 앱 내부 mock을 활성화합니다 |
| `shared-local` | 기존 호스트 인프라이며 Redpact가 시작하거나 제거하지 않습니다 |
| `remote` | 기존 원격 엔드포인트이며 Redpact가 시작하거나 제거하지 않습니다 |

종류 이름만으로 소프트웨어가 설치되거나 mock이 구현되지는 않습니다. 실제 동작하는
연결만 선언하세요. 의존성마다 고정 정의 하나를 사용하며 선택 가능한 모드나 추천은
없습니다. 기본 설정이 시작 서비스·의존성 서비스·바인딩을 제공하고 Compose 선행
의존성이 서비스 집합을 확장합니다. 변수 바인딩만으로 대상 서비스를 시작하지 않습니다.

## 공통 설정과 독립 실행

`rulesRoot`는 공통 설정 위치입니다. Compose·Dockerfile·앱·테스트 경로는 실행하는
체크아웃에서 해석하므로 기능 작업은 자신의 코드를 사용합니다. 실행마다 새 컨테이너와
네트워크를 소유합니다. 설정 공유가 환경 재사용을 허용하지는 않습니다. 워크트리 선택
파일과 의존성 overlay는 실행에 영향을 주지 않습니다.

실제 체크아웃으로 `configure` 검증을 호출하세요. 검증은 서비스를 시작하거나 연결을
입증하거나 승인을 부여하지 않습니다. 실행은 설정을 캡처하고 리소스 준비·상태 확인·
테스트 후 자신의 리소스만 제거합니다. 독립적으로 운영되는 공유·원격 서비스는 계속
실행되므로 테스트가 fixture 데이터를 격리해야 합니다.

앱 바인딩과 공통 러너 환경은 별도로 명시합니다. Integration과 Playwright 모두
`tests.env`와 같은 연결 파일 형식을 받습니다. 선언은 [설정](configuration.md), DNS·
공유 호스트 접근·브라우저 origin은 [러너 연결](execution.md#러너-연결)을 보세요.

> 작성하고 실제 소비자에서 각 연결을 검증해줘. 설정 검증과 런타임 증거를 구분해줘.

[프로젝트 설정](first-project.md) 또는 [첫 변경 검토](review-workflow.md)로 이어가세요.
