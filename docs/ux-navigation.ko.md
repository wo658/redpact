# 검토 작업 공간 탐색

뷰어는 하나의 프로젝트와 체크아웃을 선택합니다. 코딩 호스트가 작업 탭, 파일 편집,
Git 변경 작업을 맡으며 Redpact는 작업 공간 탭 관리, File Viewer, Git Graph를
중복 제공하지 않습니다. 일반적인 요청은 채팅에서 [MCP](interfaces.md)로 시작합니다.
검토 화면을 여는 것만으로 실행하지 않습니다.

## 화면 구조

```text
Redpact 검토 작업 공간
├── 연결 / 시작
│   ├── 연결 상태와 재시도
│   └── 프로젝트 연결 / 관리
├── 프로젝트 선택
│   ├── 연결된 프로젝트 선택
│   └── 프로젝트 연결 / 보존된 프로젝트 관리
├── 현재 작업 [기본 페이지]
│   ├── 체크아웃 선택
│   ├── 설정 진단과 승인 정책
│   ├── 실행 승인 대기 → 요청 검토
│   ├── 진행 중 실행 → 실행 검토
│   ├── 주의가 필요한 정리 → 실행 검토
│   ├── 최근 근거 → 실행 검토
│   └── 채팅용 체크아웃 맥락 복사
├── 실행 이력 [페이지]
│   ├── 체크아웃 선택
│   ├── Unit / Integration / Playwright 기록
│   ├── 이전 / 최신 실행 페이지 이동
│   └── 실행 검토 [상세]
│       ├── 실행과 체크아웃 식별자
│       ├── 결과, 정리와 관찰된 실패
│       ├── 캡처된 요청 상세와 대기 중 요청의 명시적 승인
│       ├── 기록된 출력 / 소스 / 케이스 결과 / 이미지 / 첨부
│       ├── 취소 또는 지원되는 정리 재시도
│       └── 채팅용 실행 맥락 복사
├── 도구 [기본 접힘]
│   ├── Container: 별도 수동 환경과 복구
│   ├── Tests: Unit / Integration / Playwright 목록과 명시적 실행
│   ├── Dependencies: 고정 정의와 환경 변수 바인딩
│   ├── Project settings: 애플리케이션과 테스트 설정
│   └── Worktrees: 읽기 전용 변경과 기존 근거 화면
│       ├── Diff와 해당 Test / Playwright / Log / Environment 탭
│       └── 선택적으로 체크아웃 없는 브랜치의 커밋 비교
└── 설정
    ├── 테마 / 언어 / 줄바꿈
    ├── 실행 승인 정책
    └── 인스턴스 설정
```

## 대상과 방문 기록

프로젝트를 선택하면 현재 작업을 엽니다. 체크아웃 선택은 상태·이력·근거의 대상을
명확히 하며, 실행 검토는 현재 선택이 달라도 기록된 체크아웃을 표시합니다. 프로젝트
Tests는 기본 체크아웃의 목록입니다. 해당 실행 버튼의 대상이 다른 선택 체크아웃으로
조용히 바뀌지 않습니다.

사이드바 목적지와 체크아웃 변경은 브라우저 방문 기록을 사용합니다. 네이티브 뒤로·앞으로도
같은 History API를 사용합니다. 새로고침하면 URL 목적지를 복원하지만 입력 초안, 파일
선택과 스크롤 위치를 영구 작업 공간으로 저장하지 않습니다. 같은 위치를 반복 선택해도
방문 기록을 중복 생성하지 않습니다. 모바일에서는 목적지를 선택하면 사이드바를 닫습니다.

`get_review_context`는 연결된 뷰어의 상대 `reviewPath`를 반환합니다. 예를 들어
`/?project=<projectId>&page=review&kind=unit&id=<executionId>&worktree=<worktreeId>`입니다.
해당 인스턴스의 출처와 함께 사용하세요. 기록이 없거나 일치하지 않으면 진단을 표시합니다.
프로젝트 연결 정보가 없거나 프로젝트가 더 이상 목록에 없는 보존 실행도 종류와 ID로
직접 열며, 다른 프로젝트를 선택하거나 연결하지 않습니다.
검토 링크는 새 실행이나 소스 최신성의 증명이 아닙니다.

## 필요한 상세만 열기

현재 작업은 승인 대기, 진행 중 작업, 미완료 정리를 최근 결과와 구분합니다. 과거 이력을
페이지로 탐색하더라도 오래된 활성 실행이나 정리 문제를 숨기지 않습니다. 간결한 MCP
요약은 반환하는 상세 수를 제한하므로 기록된 근거에서 제공되는 전체 맥락을 확인하세요.
새로고침 실패 시 표시 중인 근거가 오래됐을 수 있음을 알립니다.

도구는 기본적으로 접혀 있고 브라우저 저장소를 쓸 수 있으면 명시적인 표시 선택을
기억합니다. 고급 화면에 직접 진입하면 관련 탐색을 펼칩니다. 워크트리 검토는 읽기 전용
비교와 실행 근거를 유지하며 커밋·폐기·머지·PR 발행은 호스트 에이전트가 맡습니다.
백엔드 Git workflow의 기존 계약은 유지합니다. [Git 작업](git.md)을 참고하세요.

홍보용 푸터 링크, 자체 작업 탭, GitHub 연결 제어와 에이전트 플러그인 업데이트 패널은
뷰어에서 제외합니다. 런타임 설치와 호스트 플러그인 관리는 선택한 설치 방식에서
담당합니다. [설치](installation.md)를 참고하세요.

## 근거와 결정

실행 결과, 소스 최신성, 사람의 수락은 서로 다른 사실입니다. 최신성을 확인하지 못하면
명시적으로 표시합니다. 승인은 검토한 실행만 허용하며 코드 수락이나 머지 권한을 기록하지
않습니다. Ask 요청은 지원되는 App 카드 또는 연결된 뷰어의 명시적인 조작으로 승인할 수
있습니다. 모델의 텍스트나 숨겨진 UI 작업 호출은 사람의 승인을 대신하지 않습니다.

실행 상세는 캡처된 Integration·Playwright 소스를 사용하며 현재 소스로 대체하지 않습니다.
Unit은 전체 명령 출력을 보존합니다. 정리 실패는 테스트 결과와 함께 해결 가능한 상태로
남습니다. 체크아웃이 제거되어도 근거는 유지됩니다. 상세 계약은 [결과](results.md),
[실행](execution.md), [프런트엔드 규칙](frontend.md)을 참고하세요.
